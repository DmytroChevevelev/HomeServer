# Implementation Plan: Device List with Bootstrap and Status Filter

**Branch**: `006-device-list-bootstrap` | **Date**: 2026-05-22 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/006-device-list-bootstrap/spec.md`

## Summary

Replace the Angular default template with a Bootstrap navbar shell, install Bootstrap as a global stylesheet, connect `DeviceListComponent` to the existing `DevicePagesFacade`, render all registered devices in a Bootstrap table with color-coded status badges, and add a client-side status filter control. Fix the existing `normalizeStatus()` bug that misinterprets the API's `"active"` / `"stale"` status values. No backend changes are required.

## Technical Context

**Language/Version**: TypeScript 5.7 / Angular 19.2 (standalone components, `esbuild` builder)

**Primary Dependencies**:
- `bootstrap` 5.x — npm package, CSS-only import via `angular.json` styles array
- `@angular/common` — `CommonModule` for `*ngFor`, `*ngIf`, `[ngClass]`
- `@angular/router` — `RouterLink`, `RouterOutlet`
- Existing: `DevicePagesFacade`, `DevicesApiService`, `device-pages.models.ts`

**Storage**: None (frontend-only feature; no new API calls, no persistence)

**Testing**: Karma + Jasmine (`ng test`), `ChromeHeadless`

**Target Platform**: Browser (Angular SPA served via `ng serve` / `ng build`)

**Project Type**: Web application — Angular SPA frontend consuming .NET 9 REST API

**Performance Goals**: Filter operations are synchronous, in-memory — imperceptible latency at any realistic device list size

**Constraints**: No third-party Angular UI libraries (ng-bootstrap, Angular Material, etc.); Bootstrap CSS classes only

**Scale/Scope**: Device list expected to be <1000 rows; client-side filtering is appropriate

## Implementation Phases

### Phase 1 — Bootstrap Setup (US1 prerequisite)

**Goal**: Bootstrap CSS available globally; Angular template removed.

**Tasks**:
1. Install `bootstrap` npm package in `frontend/`
2. Add `node_modules/bootstrap/dist/css/bootstrap.min.css` to `angular.json` styles array
3. Replace `app.component.html` with Bootstrap navbar + `<router-outlet>`
4. Clear `app.component.css` of Angular default placeholder styles

**Verification**: `ng build` succeeds; `http://localhost:4200` shows navbar and no Angular placeholder.

---

### Phase 2 — Device List Rendering (US1)

**Goal**: Device list populated from `GET /api/devices` in Bootstrap table with status badges.

**Tasks**:
1. Add `StatusFilterOption = DeviceStatus | 'all'` to `device-pages.models.ts`
2. Fix `normalizeStatus()` in `DevicePagesFacade`: map `'active'` → `'online'`, `'stale'` → `'offline'`
3. Implement `DeviceListComponent`:
   - Inject `DevicePagesFacade` (constructor injection)
   - `ngOnInit()`: call `facade.getDeviceList()`, populate `allDevices` and `uiState`
   - `filteredDevices` getter: filter `allDevices` by `selectedStatus`
   - `badgeClass(status: DeviceStatus): string` method returning Bootstrap class string
4. Implement `device-list.component.html`:
   - `*ngIf` on `uiState.status === 'loading'` → Bootstrap spinner
   - `*ngIf` on `uiState.status === 'error'` → Bootstrap `alert-danger`
   - `*ngIf` on `uiState.status === 'empty'` → Bootstrap `alert-info`
   - `*ngIf` on `uiState.status === 'ready'` → Bootstrap `table table-hover` with `*ngFor` over `filteredDevices`
   - Status column: `<span class="badge" [ngClass]="badgeClass(device.status)">{{ device.status }}</span>`
5. Minimal `device-list.component.css`: optional container padding only, no structural overrides

**Verification**: Navigate to `/devices` with backend running; rows appear with correct status badges.

---

### Phase 3 — Status Filter Control (US2)

**Goal**: Bootstrap dropdown or button-group filter for status.

**Tasks**:
1. Add `selectedStatus: StatusFilterOption = 'all'` field to `DeviceListComponent`
2. Add `setFilter(status: StatusFilterOption): void` method
3. Add Bootstrap filter control in template above the table:
   - Bootstrap `<select class="form-select">` with options: All, Online, Offline, Unknown
   - Bind `(change)` to `setFilter()`
4. `filteredDevices` getter filters `allDevices` when `selectedStatus !== 'all'`

**Verification**: Select "Offline" → only offline devices shown; select "All" → all devices return; select value with no matches → empty-result message shows.

---

### Phase 4 — Unit Tests

**Goal**: Automated test coverage for component behavior.

**Tasks**:
1. `device-list.component.spec.ts`:
   - Loading state renders spinner
   - Error state renders `alert-danger`
   - Empty state renders `alert-info`
   - Ready state with 3 mocked devices renders 3 `<tr>` rows
   - Filter set to `'offline'` with mixed-status data renders only matching rows
   - Filter reset to `'all'` renders all rows
2. `device-pages.facade.spec.ts` (add 2 tests):
   - API returning `{ status: 'active' }` maps to `DeviceStatus 'online'`
   - API returning `{ status: 'stale' }` maps to `DeviceStatus 'offline'`

**Verification**: `ng test --browsers=ChromeHeadless` — all tests pass.

## Key Design Decisions

| Decision | Rationale |
|---|---|
| Bootstrap CSS-only (no ng-bootstrap) | Minimal dependency footprint; CSS classes sufficient for required components |
| `filteredDevices` as getter | Simpler than pipe or RxJS; avoids extra test surface |
| `badgeClass()` on component | Keeps Bootstrap class names out of the data/facade layer |
| Filter options: All/Online/Offline/Unknown (no Warning) | API only emits `active`/`stale`; `warning` not sourceable currently |
| Fix `normalizeStatus()` in facade | Bug: API `active`/`stale` were falling through to `'unknown'` |
